# NOT_BUGS — known intentional divergences in twmb/avro

Deliberate design choices. Findings against them are not bugs.

**Usage:** this file is a filing-time filter, not round preamble. Before filing
any finding, read the `## Index` below; if a candidate plausibly matches an
entry, read that entry and its citations. File the finding only if it does NOT
match. New confirmed divergences get appended here (claim + rationale +
citations) with an Index line — see AUDIT_CORE.md's feedback loop.

**Adjudication labeling:** every entry states WHO decided it —
maintainer-stated (the maintainer ruled on the trade-off explicitly, with
date) vs inferred-from-consistency (an auditor derived the intent from code
structure, pins, and history). A maintainer-stated entry is settled policy;
challenging it requires new executed evidence AND a maintainer decision. An
inferred entry can be re-opened by an overseer recommendation alone.
Entries predating this convention are inferred-from-consistency unless they
say otherwise.

## Cross-implementation divergence policy (Java vs fastavro vs spec)

Relocated from AUDIT_CORE.md 2026-07-20 (this is the live copy; the
entries below cite it by name). When twmb's behavior on some input could
match Java, fastavro, or the spec and they disagree, resolve by this
order — NOT by spec-literalism, and NOT by "matches reference X" alone:

1. **Correctness/safety is absolute.** Never accept an input that yields silently wrong output, unresolvable ambiguity, or a DoS/security issue. If accepting risks that, reject — regardless of what any reference does.

2. **Otherwise lean PERMISSIVE — least surprise, maximum interop.** Prefer the more relaxed behavior: if EITHER Java or fastavro safely accepts an input, lean toward accepting it too; if the spec is loose, be loose even when an impl is strict. A user whose data one major impl accepts is surprised when twmb alone rejects. Strictness (rejecting) is earned only by rule 1, never by "the spec/Java technically forbids it" when accepting is safe.

   **2a. Rule 2's precondition is a reference that ACCEPTS. Reference SILENCE is not a reference SPLIT.** A split is two references with opinions that differ — that is what rule 2 breaks, and it breaks it toward the permissive one. SILENCE is neither reference having the question at all: no impl reads that attribute at that placement, no impl performs that lift, no impl has the surface. There is no "either impl accepts" to lean on, so rule 2 does not apply and **rule 4 does — decision table + HALT for the maintainer, never auto-pick.** The failure mode is specific and it has happened twice: silence gets read as tacit permission, rule 2's permissive tiebreak fires with its precondition unmet, and the outcome is recorded as reference-derived when nothing derived it. Both of this walk's decision reversals were that error — #33's parameters-fill (NO implementation performs the lift, so none could bless it) and a primitive's empty `doc` (Apache Avro has no doc slot at that placement, so its silence was read as a drop). Test to apply: name the reference LINE that accepts. If you cannot, you have silence, and the honest outputs are a HALT, or — where this package's own adjudicated posture already governs the placement — that posture, cited as this package's, never as the reference's.

3. **The spec is an INPUT, not the sole authority.** A decisive spec resolves a case only when it agrees with rules 1–2. A *strict* spec does not force a reject if both impls safely accept; a *loose* spec is honored over a strict impl.

4. **Genuine toss-up → table + HALT for the maintainer.** When there is a real tradeoff and no clear least-surprise winner, present a decision table (option / spec / Java / fastavro / what the user gains / surprise / corruption-risk) and stop. Never auto-pick a divergence.

5. **Record every resolution in NOT_BUGS** with the spec citation, the Java/fastavro behavior, and which rule decided it.

Instance: D (fixed-union size masking) — spec + fastavro accept (safe: a reorder-decodable value, no corruption), Java rejects (bug-for-bug 1.8.x compat; its own comment admits the spec-divergence). Rules 2+3 → be relaxed, **accept** (fold size into branch selection). The earlier "match Java, document as a deliberate residual" resolution was wrong: it applied rule "matches Java" without the spec or the permissive lean.

## Entries

1. **Writer-union resolution is fail-fast at `Resolve` / `CheckCompatibility`** — every writer branch must be compatible with the reader; the first incompatible branch returns eagerly. Java's `Resolver.WriterUnion` defers via per-branch `ErrorAction` to decode time; we don't. Rationale: internal consistency with the rest of the package (`resolveEnum`, `resolveReaderUnion`, `resolveUnionUnion`, `resolveNode`, `validateDefault` are all fail-fast). See the doc comment on `checkWriterUnion` (compat.go) and `resolveWriterUnion` (resolve.go).

2. **`DecodeJSON` on a resolved schema consumes WRITER-shaped JSON and applies full writer→reader resolution.** Its JSON path decodes writer-shaped JSON with the writer schema, re-encodes to writer binary, then runs the resolving binary decode (`decodeJSONResolved` in json_codec.go; `s.resolveWriter` is set in `Resolve` only when writer≠reader, else nil and DecodeJSON decodes against the reader node). Matches Java's `ResolvingDecoder` wrapping a `JsonDecoder` built with the WRITER schema (`Resolver.EnumAdjust.resolve` at `Resolver.java:388-399` maps writer enum symbol absent from reader to reader's enum default; fastavro `_read_py.py:281-288` same — both read the WRITER symbol first) and equals `resolved.Decode` of the writer binary carrying the same branch choices: the intermediate decodes with `TaggedUnions` so union values keep their `{"branch": value}` envelope, and the re-encode's tagged-map dispatch routes them back to the exact branch — tagged writer JSON keeps the named branch even when its value also satisfies an earlier sibling (Java `JsonDecoder.readIndex` reads the label straight to the branch index), while bare writer JSON commits to the documented first-match branch (entry #5), which the envelope then pins through the re-encode. Two consequences not to re-flag: (1) input is writer-shaped (reader-shaped JSON may error on dropped writer fields — correct); (2) it is a decode→re-encode→resolve round-trip, not a single-pass resolving JSON decoder (reuses the tested binary resolver). Pinned by `TestRegression_ResolvedDecodeJSONMatchesBinary`, `TestRegression_ResolvedJSONTaggedUnionValueMatchesBinary`/`TestRegression_ResolvedJSONTaggedUnionBranchIdentity`, and the input-form × collision-shape × resolution matrix `TestMatrix_ResolvedJSONUnionInputForms` (fastavro `json_reader`+migration calibrated in `TestDifferentialFastavroResolvedJSONUnion`).

3. **Decimal JSON decode accepts the spec form (codepoint-mapped string) and bare numbers (`0.33` unquoted).** Encode emits the spec form only; Java is strict (codepoint-only). The bare-number leniency handles hand-edited JSON and twmb's pre-fix output. Quoted-numeric strings (e.g. `"0.33"`, goavro's `EnableDecimalBinarySpecCompliantEncoding` form) are NOT accepted as numeric — interpreted via codepoint mapping per spec, since a quoted-numeric input can't be disambiguated from a spec-form byte sequence. The codepoint-mapped string is accepted only as valid JSON (control/high bytes escaped as `\u00XX`); raw unescaped form rejects. See `decodeBytes` and `decodeFixed` in json_decode.go and `TestRegression_DecimalBytesJSONStringIsCodepointForm`.

4. **JSON decoder accepts non-canonical multi-byte varints** for null-union branch indices (e.g. `0x80 0x00` for index 0). Java's `BinaryDecoder.readIndex` does the same. Not a divergence — listed here to prevent re-finding it as one.

5. **Bare (untagged) JSON union decode commits to the FIRST declaration-order branch of the matching JSON token class — the writer's branch (and any CustomType on a later same-class branch) is NOT recoverable.** The untagged wire carries the bare value only: `int32(7)` and `int64(7)` into `["long","int"]` both produce wire byte `7`, so the loss is information-theoretic, not a dispatch bug. Decode-into-`any` yields the first token-class branch's Go type; a transforming CustomType on a non-first same-class branch is silently skipped (Pattern 13b — compare transformed values, not just success). `TaggedUnions` fully recovers the branch (tagged wires `{"int":7}`/`{"long":7}` differ). Java has no bare-union JSON decode (its JsonDecoder rejects with "Expected start-union"); the bare default is twmb's goavro/hand-edited leniency (AVRO-2899). Do NOT add branch-guessing heuristics. Pinned by `TestRegression_UntaggedUnionBranchClassFirstMatch`.

6. **JSON encode of an Avro string containing invalid UTF-8 coerces each invalid byte to U+FFFD; binary preserves the bytes verbatim.** An RFC 8259 JSON string cannot carry a raw non-UTF-8 byte, so byte-faithful binary↔JSON parity is impossible — inherent to the wire formats. Verified byte-for-byte against Java in CI (`TestDifferentialJavaInvalidUTF8`): Java's `JsonEncoder` emits identical U+FFFD bytes (`ef bf bd`; `"A\xffB"` → `22 41 ef bf bd 42 22`) and Java's `BinaryEncoder` re-encodes raw bytes verbatim, for top-level strings, record fields, and map keys at every depth. twmb matches Java on both wires (`appendJSONString` json_codec.go vs verbatim `doSerString` ser.go). Do NOT "fix" either side toward the other. Pinned by `TestRegression_InvalidUTF8StringBinaryVerbatimJSONCoercion`.

7. **Local-timestamp encode uses wall-clock-as-UTC**, mirroring Java's `TimeConversions.LocalTimestampMillisConversion`. Some auditors have flagged this as "should encode the absolute moment"; it shouldn't.

8. **OCF bzip2 and xz codecs are not supported.** Java and fastavro support both. We deliberately don't carry the third-party deps (`dsnet/compress` for bzip2 write; `ulikunitz/xz` for xz). Users can register a custom codec via `ocf.WithCodec`. The built-in deps stay zstd/snappy/deflate.

9. **Whole-number floats encode against `int` / `long` schemas.** `s.Encode(&v)` for `v float64 = 42.0` against `"int"` produces wire bytes equivalent to `int32(42)`; fractional floats (`42.5`) error with "not a whole number". Java's `GenericDatumWriter` and fastavro reject float-as-int. We accept whole-number floats because `encoding/json.Unmarshal` produces `float64` for every JSON number (the common dynamic-schema flow); rejecting would force explicit conversions. Wire format unchanged. See `serInt`'s `elem.CanFloat()` arm at ser.go and `TestRegression_WholeFloatEncodesAsInt`.

10. **String-form float/double defaults are accepted at the single-field OUTER type only.** `{"type":"float","default":"1.5"}` on a record field parses (Java's `parseField` coerces a TEXTUAL default to a DoubleNode for float/double fields, Schema.java:1899-1902), but the same string inside a nested container's default does NOT — Java's coercion is at the field level and does not recurse. twmb matches that scope exactly rather than generalizing it, so a string default deeper in a compound value still rejects. Do NOT "fix" the asymmetry: it is Java's, and widening it would accept values Java rejects. Verbatim: archive (2026-07-28 #1).

11. **(tombstone, fully netted) DOS-resistance defense-in-depth — twmb caps values Java and fastavro leave unbounded**: `errTooDeep` recursion 1000; `maxZeroByteItems`/`maxMapPreAllocSize` 4096; `WithMaxBlockBytes` + `WithMaxDecompressedBlockBytes` 64 MiB plus the per-block `zeroRun <= maxOCFZeroByteSlack` cap; `ocfMetadataSafetyLimit`/`ocfSchemaSafetyLimit`; `maxIndirectDepth` 5; `decimalScaleLimit` 65536; `maxDecimalUnscaledBytes` 32 KiB; `maxRatInputLen`. The standing lesson: every reader-side cap needs a producer-side compliance check — the sole exception is the OCF block-size pair, reader-only by design (#12) — an exception now ASSERTED as a cell (`TestInvariant_OCFBlockCapsStayReaderOnly`) rather than merely written down, on the type system's own evidence: `WithMaxBlockBytes` is a ReaderOpt, so producer enforcement is not absent but UNEXPRESSIBLE. Nets: **`TestMatrix_CapProducerCompliance` is the COMPLETENESS question for this family** — cap × applicability × carrier {value, DEFAULT} × nesting {flat, in-record, in-array, in-map} × wire, with `TestInvariant_EveryCapIsClassified` failing on any cap landing without a row. Three facts it established: **the list above is NOT the set of caps** (its first run surfaced ten more bounds); **a cap is not one question** — the DEFAULT carrier is pre-encoded by a separate walk sharing no code with the serializers, and its face went unfixed for four rounds after the value face closed; and **not every bound is a wire cap** — allocation hints, probe buffers, error-message bounds, caller-reader guards, the writer's flush threshold and a Go-target-type depth each refuse no wire and are recorded not-applicable WITH the reason, since a forced cell is vacuous. The invariant is PER-WIRE self-consistency, deliberately not "rejects on every wire": `maxZeroByteItems` is binary-only because JSON text cannot amplify. Also `TestMatrix_SelfReadableAtScale`, the DoS battery, the hostile-size matrices, `TestRegression_DecimalUnscaledLengthDoS`. Do not re-file these as "too restrictive" — deliberate. Re-opens: a new cap landing without a `TestMatrix_SelfReadableAtScale` generator, or a reference impl adopting a conflicting bound. Verbatim: BUG_AUDIT.md §Distillation archive (2026-07-25 #3).

12. **OCF block-size caps (`WithMaxBlockBytes` / `WithMaxDecompressedBlockBytes`) are READER-ONLY by design — the deliberate EXCEPTION to the producer-compliance lesson above.** The writer has NO block-size compliance check, intentionally. A default writer CAN emit a single block (e.g. an 80 MiB datum, unsplittable by spec) that a default reader refuses; this is EXPECTED, not the self-incompatibility bug class. Rationale: block-size caps defend against UNTRUSTED input (a self-produced file isn't untrusted); matches Java's `DataFileWriter` and fastavro (no writer-side cap); a single large datum is legitimate and unsplittable, so producer enforcement could only error on a valid value; the reader errors actionably naming its option. Producer-side enforcement was implemented and reverted (data-loss trap at `flush` + unclosable compressed-cap residual). Contract in `ocf` doc's "Block size limits"; pinned by `TestRegression_OCFLargeDatumReaderCap`. AUDITORS: do not re-file "default writer emits a block the default reader rejects" as self-incompatibility, and do not re-add producer-side block-size enforcement.

13. **Degenerate-cardinality types parse: size-0 fixed, zero-symbol enums, zero-branch unions.** All three are reference-legal. size-0 fixed: Java CI decodes it (`TestGenericDatumReader.arrayOfZeroLengthFixedAcceptsLargeCount`, `minBytesPerElement(createFixed(…,0))==0`), fastavro/Apache Python round-trip (executed), avro-rs `as_u64` accepts 0. Empty union: Apache `share/test/data/schema-tests.txt` vector 016 (`[  ]` → `[]`, Rabin `-1241056759729112623`, live in `TestApacheSchemaTestsVectors`), fastavro/Apache Python parse, Java `UnionSchema` ctor no-ops, avro-rs accepts. Empty enum: Java `parseEnum`→`EnumSchema` ctor (`Schema.java:1910-1933`/`1089-1104`) has no count check, fastavro/Apache Python parse, avro-rs checks dups/default only. hamba REJECTS empty enums (hamba#295) — twmb sides with the four references. size-0 fixed is usable; empty enums/unions are parseable-but-unusable (encode/decode errors, never panics; defaults reject). Nested-union rejection still covers `[[]]`. A MISSING required attribute still rejects (`{"type":"enum"}` no symbols, `{"type":"fixed"}` no size). Union-ness discriminated by `s.union != nil`; do not "simplify" to `len() > 0`. Pinned by `TestRegression_FixedSizeZero*`, `TestRegression_EmptyEnum*`, `TestRegression_EmptyUnion*`, `TestHambaEmptyEnumSymbolsAccepted`, oracle vector 016.

14. **Valid JSON for special floats.** EncodeJSON emits `"NaN"` / `"Infinity"` / `"-Infinity"` as quoted strings by default (RFC 8259 valid). Java's JsonEncoder emits bare tokens (RFC 8259 invalid); fastavro defers to `json.dumps(allow_nan=True)` (also bare). twmb is the only impl whose default output round-trips through strict JSON consumers (jq, Postgres jsonb, browser parsers). `LinkedinFloats` option swaps to goavro convention (NaN→null, ±Inf→±1e999). DecodeJSON accepts all four forms.

15. **Magnitude-based decimal precision count.** `checkDecimalPrecision` counts digits of the unscaled big.Int magnitude. Java's `BigDecimal.precision()` and fastavro's `len(digits)` count *significand* digits (e.g., `BigDecimal("1E10").precision() == 1`). Go's `big.Rat` has no significand/exponent split, so the magnitude count is structurally forced — and is the safer direction (round-trip-safe regardless of how the receiver counts).

16. **Implicit null default for `["null", T]` unions.** When the schema declares `["null", T]` without an explicit default, twmb infers `null` as the default. Java and fastavro require it explicit (no inference). Improves schema-evolution ergonomics for the canonical nullable pattern. See schema.go's union-default synthesis and `TestParseImplicitNullDefault`. **Emission clause (2026-07-25):** because the inference is twmb-only, SchemaFor must WRITE the default rather than rely on it — the emitted text is what a caller publishes, and a foreign reader that never infers cannot read pre-field data without it. That makes the emission spelling-sensitive in a way the in-process behavior is not: the parse-side synthesis routes through the spelling-agnostic `aschema.isNullBranch`, so a wrapped-null union decoded fine in twmb while its emitted schema silently omitted `"default":null` (fastavro EXECUTED: `SchemaResolutionError: No default value for field F`, while the bare twin reads `{'F': None}`). SchemaFor's fill now routes through `isNullBranchTree`, the `any`-tree mirror of the same predicate. Nets: `TestRegression_SchemaForNullFirstDefaultWrappedNullBranch` (asserts the EMITTED text, not the metadata surface), `TestMatrix_SchemaForNullBranchSpellingParity`, `TestDifferentialFastavroSchemaForNullSpelling` (readresolve arm — a foreign reader over the emitted schema).

17. **Per-schema custom-type registration scope.** `CustomType` passed via `SchemaOpt` to `Parse`; the decoder map is frozen on the resulting `Schema`. Java's `LogicalTypes.REGISTERED_TYPES` (LogicalTypes.java:58) is a process-global ConcurrentHashMap; fastavro's `LOGICAL_READERS`/`LOGICAL_WRITERS` are module-level dicts. twmb's per-Schema scope avoids global-state hazard. Re-registration is order-stable with `ErrSkipCustomType` fall-through, vs Java/fastavro last-write-wins.

18. **Eager schema-resolution fail.** `Resolve` and `CheckCompatibility` reject incompatible writer-union → reader-non-union pairs at config time; Java (`Resolver.WriterUnion`) and fastavro (`read_union`) defer to decode time via per-branch ErrorAction. A producer that narrowed but never emits the dropped branch must update its schema before `Resolve` accepts; in Java/fastavro decode-time errors can fire months later. Deliberately stricter (generalizes the writer-union case).

19. **Strict UUID format on decode — for the `[16]byte` (and `*uuid`-typed) target.** `parseUUID` requires the 36-char hex-dash canonical form per RFC 4122. Older JDKs (<15) accepted variable-length hex segments (AVRO-2497); modern JDK matches twmb. fastavro's `uuid.UUID(data)` accepts five formats. twmb aligns with modern strict. NOTE: applies only to the parse-into-`[16]byte` path; a plain Go `string` target for a `uuid`-logical schema is decoded as a raw Avro string with NO UUID-format validation (deser.go — "UUID-on-string is wire-equivalent to plain string"), symmetric on encode.

20. **Snappy CRC verification on OCF read.** twmb explicitly verifies the trailing CRC32 after Snappy decompression (`ocf.go`); Java's `SnappyCodec.decompress` also verifies; fastavro reads the 4 CRC bytes but never compares (`_read_py.py:729-733`) — silent corruption pass-through.

21. **JSON DecodeJSON fills schema-declared defaults for absent record fields.** A JSON object missing a field with a schema default materializes the default into the target. Matches fastavro (`io/json_decoder.py:55-78`); Java's JsonDecoder rejects missing fields outright (`JsonDecoder.java:498-530`). Aligned with lenient-acceptance + least-surprise. See `iterateRecordFields`'s `fillDefault` callback and `TestSpecJSONDecodeFillsDefaultForMissingField`.

22. **`CustomType.Encode` is bypassed for default-filled record fields; `CustomType.Decode` is applied.** Defaults live on the Avro-native side of the directional contracts (encoder: Go-domain→Avro-native; decoder: Avro-native→Go-domain), stored in parsed Avro-native form (`json.Number`/`[]byte`/`string`), so the encoder has nothing to convert; the decoder still does. Binary: `encodeDefault` (resolve.go) never reaches `custom[node]`, and pre-encoded `f.defaultBytes` roundtrip through the wrapped deser on decode. JSON matches: `appendJSONFieldDefault` (json_codec.go) recurses with `custom=nil`; `applyFieldDefault` (json_decode.go) dispatches through the wrapped deser. The encode-side bypass matters for GoType=nil patterns (logging/validation/dispatch). See `TestRegression_DecodeJSONFillsDefaultThroughCustomDecoder` and `TestRegression_EncodeJSONBypassesCustomEncoderForDefaultFill`.

23. **Wrapped-form name references accepted, including forward refs.** `{"type":"Node"}` is accepted as a name reference both when `Node` is already declared and when it's a forward reference. Matches Java's parser (`TestUnionSelfReference.java:50`). fastavro and hamba reject the wrapped form. 24. **Name references bind EAGERLY at the point of reference, in-scope-first.** A bare reference resolves against types defined so far: enclosing-namespace-qualified name first, then bare (null-namespace) — Java's `Names.get` order (`Schema.java`: `new Name(o, space)` before null-space retry; fastavro qualifies unconditionally). A reference that resolves at reference time keeps that binding; only an unmatched reference defers to finalize (same in-scope-first rule over the complete table). Java's newer `ParseContext` defers all resolution to end-of-parse and can bind differently for a pathological shape — twmb keeps the deterministic eager model. The three parallel resolvers (`resolveNamedRef`, `lookupCanonDef`, `lookupNameRef`) derive key order from one helper (`scopedRefKeys`, schema.go). Every resolver registers under exactly the wire builder's keys (fullname only; a null-ns type's fullname IS its bare name). Pinned by `TestRegression_BareNameRefBindsInScopeBeforeNullNamespace`, `TestRegression_MetadataDefaultShortNameCollisionWalkOrder`, `TestRegression_UnionForwardRefDuplicateOrderIndependent`.

25. **Parsing Canonical Form is a fingerprint surface, not a round-trip surface — `Parse(s.Canonical())` can fail for null-namespace types nested in a namespaced scope.** The PCF [FULLNAMES] transform writes every name as its fullname and drops namespace attributes; a null-namespace type's fullname is its bare name, which re-reads inside a namespaced scope as inheriting that scope — so the canonical form is ambiguous. Java's `SchemaNormalization.build` emits byte-identical ambiguity (`name.getFullName()`, no escape syntax for refs), and matching Java's bytes is the point of PCF. Do NOT "fix" the emitter at the cost of diverging fingerprints. Same limit applies to `SchemaNode.Schema()` dedup references to a null-ns type from a namespaced scope (Java's `getQualified` has the identical gap). Noted in `TestRegression_UnionForwardRefDuplicateOrderIndependent`'s lossyCanonical cases and `TestRegression_BareNameRefBindsInScopeBeforeNullNamespace`. A sibling structural limit lives at the cache splice: RESERVED usage-site attributes on a props-carrying wrapped reference (`{"type":"R","doc":...}`) cannot survive the splice-to-definition (a def cannot carry a second name/namespace/doc for its usage site); the wrapper's custom PROPS do — see #63's wrapped-reference splice-merge clause.

26. **SchemaNode.Namespace is the RESOLVED namespace; re-emission uses Java's writeName relative-namespace rule.** `Root()` populates `Namespace` for every named type — an inheriting child surfaces the inherited namespace, and `""` always means the null namespace (matching Java's resolved `getNamespace()`). `SchemaNode.Schema()`'s walker emits namespace relative to the enclosing scope: omitted when equal, `"namespace":""` to escape inheritance for a null-namespace type inside a namespaced scope (Java `Name.writeName`'s "null within non-null" arm), the value otherwise; dedup and references key on the FULLNAME. The as-written placement (inherited-vs-explicit spelling) is intentionally NOT preserved — schema identity (fingerprint) round-trips, not attribute spelling. See the `SchemaNode.Namespace` field doc and `TestRegression_SchemaNodeNullNamespaceEscapeRoundTrip` / `TestRegression_SchemaNodeSameShortNameDistinctNamespaces`.

27. **Aliases (type AND field) accept ANY string — deliberately NOT name-validated. Do not re-add validation.** The Avro spec §Aliases states "any string is accepted as an alias," so evolution can alias a reader's valid name to a writer's illegal/legacy name; fastavro does no alias validation (`123 !bad` parses, observed 1.12.2) and Java stores FIELD aliases as raw strings (`Field.addAlias`, Schema.java:674-677). Java's default parser DOES validate TYPE aliases (parseAliases → `NamedSchema.addAlias` → `new Name`, Schema.java:2000-2004/:847, NameValidator.UTF_VALIDATOR rejects digit-start/punctuation) — Java's own divergence from the spec sentence; the spec text + fastavro + Java-field behavior carry the permissive policy. twmb formerly grammar-checked aliases (the divergence) — now matches spec, accepting `1stField`, `com.example.legacy_x`, `weird!`, etc. Type names, field names, and enum symbols stay strictly validated; only aliases relax. The leading-dot null-namespace escape survives as a qualification rule (not a grammar gate): `qualifyAliases` (schema.go) strips exactly one leading dot, so `.Name` aliases the null-namespace fullname `Name`. Resolution matches aliases as plain strings; PCF strips aliases so fingerprints are unaffected. See `qualifyAliases` (schema.go), `TestRegression_AliasAcceptsAnyString`, `TestRegression_LeadingDotAliasNullNamespace`.

28. **OCF Writer: value errors recover; I/O and compression errors poison.** A failed `Encode` whose error is a value error discards only that datum — `AppendEncode` is append-only into the block buffer, so not adopting the returned slice restores the pre-call state; previously accepted datums survive and flush, and the Writer stays usable. Mirrors Java `DataFileWriter.append`'s buffer truncation. I/O, compression, and flush errors poison (sink state unknowable); `Close` still closes the codec in the poisoned state. See `Writer.Encode`'s doc (ocf.go) and `TestRegression_OCFWriterValueErrorRecovers` / `TestEncodeError` / `TestCompressError`.

29. **big-decimal canonical-scale (no trailing-zero preservation).** AVRO-4124 wire layout: inner-bytes-framed unscaled (two's-complement big-endian) + zigzag varint scale; only Java and avro-rs implement it (fastavro and hamba do not). twmb encodes `*big.Rat` natively via scale derivation: for `n/d` with `d = 2^a · 5^b`, canonical scale is `max(a, b)`; non-terminating rationals (`1/3`) are rejected at encode rather than rounding (mirrors `ratToUnscaled`). Java's `BigDecimal` preserves user-declared scale (`"3.14"`→scale 2, `"3.140"`→scale 3) — twmb cannot reproduce this because `big.Rat` reduces to lowest terms (both become `157/50`, canonical scale 2). Equivalent to `BigDecimal.stripTrailingZeros()` before Java's encoder. Decoder tolerates negative scale. See `serBigDecimal` / `deserBigDecimal` / `finiteScale` / `parseBigDecimalPayload` and `TestSpecBigDecimalWireFormat` (Java ground-truth byte match against `bigdec.avro`).

30. **Schema metadata numerics normalize by VALUE, not by syntax or Go type — `Props` uses value-based dispatch; `Fields[].Default` adds schema-width-faithful narrowing on top.**

   `*.Props` (no schema attached): the literal's mathematical value drives dispatch — exact integer fitting int64 → `int64` (e.g. `42`, `1e3`, `9.5e17`, `9.2233720368547758e18`); integer-syntax beyond int64 (`99999999999999999999`, no `.`/`e`) → `json.Number` (preserved); fractional/exp syntax beyond int64 (`9.223372036854775808e18`) → `float64`; `1e308` → `float64`; `1e1000` → `float64(±Inf)`; non-integer (`1.5`, `1e-3`) → `float64`. Syntactic shape doesn't affect type — `1e3` and `1000` both return `int64(1000)`. Matches Java's `LongNode` + fastavro's Python int (both preserve precision; Go's stdlib `Unmarshal`-into-any forces every number to `float64`). Value-based dispatch eliminates a metadata-vs-wire divergence where `9.2233720368547758e18` against a long had wire `int64(...800)` but metadata `float64(~2^63)`.

   `Fields[].Default` (schema-typed): narrowed to the schema's wire width — `int`→`int32`, `long`→`int64`, `float`→`float32`, `double`→`float64` (matching wire). Out-of-range integer defaults reject at parse. float32 narrowing surfaces overflow as ±Inf (`{"default":1e100,"type":"float"}` → `float32(+Inf)`). Matches Java's `JacksonUtils.toObject` (`JacksonUtils.java:150-155`) narrowing `DoubleNode → Float`. Unlike `Props`, numeric `Default` is NEVER `json.Number`. Programmatic round-trip via `.Schema().Root()` narrows typed numerics; wire unaffected; users must type-switch rather than asserting `.(float64)`. See `normalizeJSONNumber` + `coerceMetadataDefault` in `schema_node.go` and `TestRegression_SchemaMetadataNumericPrecisionPreserved`.

31. **Precision policy: the READER schema is the user's contract.**

   (a) **When the reader schema is lossy (`float`/`double`), encode AND decode both silently IEEE-round.** `s.AppendEncode(int64(9007199254740993), "double")`, `json.Number("...")`, `float64(1e300)` against `"float"`, and JSON counterparts all succeed and silently round. Matches Java's `GenericDatumWriter.writeDouble(((Number) datum).doubleValue())` (`GenericDatumWriter.java:180`) and fastavro's `struct.pack("<d", datum)` (`binary_encoder.py:42-43`). Hamba is type-strict (`int64`→`Double` errors) — twmb sides with wire reality and the JVM/Python majority. Same rule for RESOLVED promotion: reader `double`/`float` over a writer int/long silently rounds at the cast — matches Java's `ResolvingDecoder.readDouble` `(double) in.readLong()` (`ResolvingDecoder.java:192`), fastavro `maybe_promote` (`_read_py.py:619-621`), hamba `createDoubleConverter`.

   (b) **When the reader schema is exact (`int`/`long`/`bytes`/`string`) and the Go target is lossy, decode is allowed ONLY IF the wire value is exactly representable.** `s.Decode(longWire(9007199254740993), &f float64)` against `"long"` REJECTS via `setLongValue`'s `intFitsFloat` arm; ≤2^53 succeed. `s.Decode(doubleWire(1e300), &f float32)` REJECTS via `setFloatValue`'s `finiteFloat32Overflows` arm (Go-type loss beyond the reader schema). Encode rejects only on inputs the target can't represent at all. See `appendAvroFloat32` / `appendAvroFloat64` / `jsonCoerceToFloat64` / `jsonNumberToFloat` / `defaultAsFloat`; `setLongValue` / `setFloatValue`; `promoteIntFloatMantissa`. Pinned by `TestRegression_DefaultFloatIntegerLossyRound`, `TestRegression_Float32NarrowingEncodeIsLossy`, `TestRegression_Float32NarrowingDecodeParity`, `TestRegression_ResolvedLongToDoubleLossy`, `TestPromotionBoundaryValues`.

32. **Logical-type mismatch under schema resolution: reader's logical wins.** When writer and reader carry different known logical types — e.g. `int+date` writer + `long+timestamp-millis` reader — twmb applies the reader's logical-type conversion to the writer's wire value after physical promotion (wire bytes reinterpreted, not converted): writer `date(2024-01-01)` → wire `int(19723)` → reader `Instant.ofEpochMilli(19723)` ≈ 1970-01-01. Java (`Resolver.java:162` stores `r.getLogicalType()`; `GenericDatumReader.java:165-175`) matches twmb (reader's wins). fastavro (`_read_py.py:660-664`) applies the WRITER's logical (returns `date(2024,1,1)`). The spec is silent (Schema Resolution `_index.md:681-725` lists only physical promotion; Logical Types 783-787 covers only unknown logicals). twmb chose Java alignment for JVM interop; downside is silent semantic confusion on date→timestamp-millis evolution. Boundary cases pinned in sandbox `TestProbe_LogicalType*` (`/tmp/avro_audit_verify/probe_logical_mismatch_test.go`). Don't re-flag: spec-silent, Java parity; a policy challenge needs cross-impl evidence Java changed or a real interop break.

33. **Field-level `logicalType` annotation on unions is lifted onto the first non-null branch.** `{"name":"ts","type":["null","long"],"logicalType":"timestamp-millis"}` (the AVRO-2015/AVRO-3014 user error) parses with the logical applied to the `long`, so `time.Time` encodes directly. Apache Avro detects and warns but does not lift (Schema.java:1871-1877); fastavro/hamba/goavro keep it as a field property only. Twmb-unique among Go impls; wire identical. The metadata API does NOT reflect the lift (`Field.Props["logicalType"]` carries it) — matching all references.
    **Spelling-agnostic:** "first non-null branch" means the first branch that is not the null TYPE in either spelling the grammar admits, through the one `aschema.isNullBranch` predicate (P20).
    **Parameters-fill (ruled 2026-07-26):** the ANNOTATION and its PARAMETERS are separate questions. Closer-to-the-type wins the annotation; the field still completes MISSING precision/scale, but only where the EFFECTIVE logical (the target's own if it has one, else the field's) is `"decimal"` — through `liftEffectiveLogical`, the same predicate the consume verdict reads, so navigation, landing and completion cannot disagree. Before this the object arm completed parameters and the union arm did not, making the verdict spelling-dependent for the same post-lift schema. No reference has an opinion, so INTERNAL CONSISTENCY governs with rule 2 breaking the tie toward accepting; the gate's side effect is unobservable, MEASURED (canonical + wire identical with the pair present, absent, and at scale 0 vs 2).
    The lift is a per-problem-shape concession, NOT "make every buggy schema work." Supported: `["null","T"]` and its object-form null twin, `"T"`, `{"type":"T"}`, each with a field-level logical and no own annotation. INTENTIONALLY unsupported: a lift onto a NON-FIRST non-null branch (`["null","string","long"]`+`timestamp-millis` targets the `string` and soft-drops). 34. **Decimal logical type accepts `float64` / `float32` input.** `s.AppendEncode(float64(3.14), {"type":"bytes","logicalType":"decimal",…})` succeeds via `tryCoerceToRat`'s float arm using `strconv.FormatFloat(f, 'f', -1, v.Type().Bits())` → `big.Rat.SetString`. Matches Java's `BigDecimal.valueOf(double)` (shortest-decimal). fastavro requires `decimal.Decimal`, hamba `*big.Rat`, goavro textual string — twmb is the only Go impl accepting native float. Passing the SOURCE bitsize to `FormatFloat` (`v.Type().Bits()`, not a hard-coded 64) is what keeps the text short: `float32(0.33)` formats as `"0.33"` rather than the float64-noise `"0.33000001311302185"`, and only the short form parses to a terminating rational — hard-coding 64 would reject the value. Float64's bounded exponent keeps magnitude under `decimalScaleLimit` (65536); `FormatFloat`'s 'f' output is JSON-valid by construction, so bypassing `boundedRatFromString`'s gates is safe. 35. **`json.Number` content is validated against the schema's contract.** json.Number's underlying string must be a valid RFC 8259 number literal.
   - Numeric schemas (int, long, float, double + logical variants date/time-millis/micros/timestamp-/local-timestamp-): decode writes the raw numeric wire value as a JSON-number-valid string, bypassing logical formatting (date wire `19723` → `json.Number("19723")`, not `"2024-01-01"`). Encode parses and validates fit. Non-finite floats reject both sides. Centralized at `formatToStringKindTarget` (deser.go), routes through `setIntegerWire`'s json.Number arm.
   - Stringy schemas (string, bytes, fixed, enum): `json.Number` is REJECTED on both encode and decode regardless of content (`"1.5"` rejects like `"foo"`) — a numeric carrier into a text/binary target is a type mismatch. `rejectJSONNumberStringTarget` (deser.go) on decode; `appendAvroString` / `rejectJSONNumberRawTarget` on encode.
   - Map keys: per-key validation via `validateJSONNumberMapKey` on decode and encode; record-as-map decode rejects on the first field name (Avro names never satisfy JSON-number grammar).
   - Decimal logical type exempt (`setDecimalRat` writes `big.Rat.FloatString`, RFC 8259-valid).

   Go stdlib's `json.Marshal(json.Number(x))` fails for invalid literals, so this matches the type's own marshaler. twmb is the only Go impl exposing `json.Number` as a decode target. See `validateJSONNumberMapKey`, `rejectJSONNumberStringTarget`, `formatToStringKindTarget`, `setFloatValue` in deser.go.

37. **JSON *string* decode is strict — matches encoding/json / Java (Jackson) / fastavro / RFC 8259, deliberately STRICTER than goavro.** Unescaped control chars (U+0000–U+001F), invalid UTF-8, and unrecognized escapes (`\x`, `\q` — only the eight JSON escapes + `\uXXXX` valid) reject in `consumeStringRaw` / `walkJSONEscapes`. `decodeJSONFloat` rejects non-JSON number grammar (`5.`, `5.e3`) via `isJSONNumber`. `DecodeJSON` rejects trailing non-whitespace (one value, no offset returned, can't stream — unlike Java's streaming JsonDecoder or goavro's `NativeFromTextual`). The encoder escapes every control/high byte, so codepoint-mapped forms round-trip in escaped `\u00XX` representation; only raw/invalid hand-written forms reject. goavro accepts raw control chars, drops the backslash on a bad escape, returns trailing bytes; twmb rejects all three. Maintainer's deliberate post-ecosystem-sweep choice — do NOT propose re-loosening toward goavro. Retained leniencies: bare untagged unions, special-float tokens, whole-number-float-as-int. Pinned by `TestDecodeJSON{InvalidEscape,RawControlChar,InvalidUTF8,TrailingContent,FloatGrammar}Rejected` and `TestSpecJSONTrailingContentRejected`.

38. **`SchemaFor` rejects logical-type tags on incompatible Go types.** Strict Go-type compatibility for every logical-type tag at build time: `,uuid` requires string / `[16]byte` / text-marshaler; `,decimal(p,s)` requires `*big.Rat`/`big.Rat`; `,date` and `,time-millis` (int wire) require `time.Time`/`time.Duration`/int8/16/32 or uint8/16; `,time-micros`/`,timestamp-*`/`,local-timestamp-*` (long wire) require `time.Time`/`time.Duration`/int, int64, uint32/64, uint; `time.Time`/`time.Duration` reject non-time logicals. `,inline` (and anonymous embeds) reject any other tag option. Prior behavior was silent drop (producing a wrong or lying schema, e.g. `,uuid` on int32 → `{string,uuid}`). Java/fastavro have no `SchemaFor` equivalent — internal-consistency-only. A logical-type tag on a field whose type matches a registered CustomType is rejected too — the custom supplies the schema, so the tag has nothing to apply to (set LogicalType/Schema on the CustomType instead); accepting it was a silent drop. Pinned by `TestSchemaForUUIDRejectsUnsupportedKind`, `TestSchemaForDecimalRejectsNonBigRat`, `TestSchemaForLogicalOnNumericKind`, `TestSchemaForTimeTypesRejectNonTimeLogicals`, `TestSchemaForInlineRejectsOtherOptions` in `schema_for_test.go`, and `TestRegression_SchemaForLogicalTagOnCustomMatchedFieldRejected` in `schema_for_scope_test.go`.

39. **Text interfaces (`TextMarshaler` / `AppendText` / `TextUnmarshaler`) take precedence over the `reflect.String` fast path and the enum int-ordinal arm — uniformly across binary and JSON, scalar and container.** Resolution order at every text-shaped site: (1) for uuid logical types a `[16]byte`-shaped type TRUSTS its raw bytes (text interface NOT consulted — the 16 bytes ARE the UUID; a round trip would let a non-canonical text method diverge binary from JSON); (2) `TextMarshaler`/`TextUnmarshaler`; (3) `reflect.String`; (4) raw bytes / enum int-ordinal. `json.Number` excluded from text dispatch. 40. **A nil `*Schema` is a programming error and methods PANIC on it — not guarded; do NOT propose returning errors for nil receivers.** Every exported `*Schema` method dereferences the receiver and panics on a nil `*Schema` with otherwise-valid args: `AppendEncode`, `Encode`, `EncodeJSON`, `AppendEncodeJSON`, `Decode`, `DecodeJSON`, `AppendSingleObject`, `DecodeSingleObject`, `Canonical`, `Fingerprint`, `String`, `Root`. `Resolve`/`CheckCompatibility` panic when either arg is nil. `*SchemaNode.Schema` and `*SchemaCache.Parse` panic on nil receiver too. 43. **A negative-zero default in INTEGER syntax (`-0`) keeps the `strconv.ParseFloat` sign on the wire (`-0.0`, identical on binary and JSON), while the metadata API collapses it to `+0.0` — a deliberate residual on a degenerate literal.** FLOAT-syntax negative zero (`-0.0`, `-0e0`) is sign-coherent everywhere — wire, `Root().Fields[].Default`, and `Root().Schema()` rebuild all preserve `-0.0` (matching Java's Jackson `DoubleNode` and fastavro). A STRING default `"-0"` is unaffected (it reaches the wire via `parseFloatAcceptOverflow`, preserving the sign like Java's `Double.parseDouble("-0")`). Do NOT "fix" the integer-`-0` wire to `+0.0` without the maintainer; the cure is worse than the residual. Pinned by `TestNegativeZeroIntegerLiteralResidual`; the float-syntax fix is pinned by `TestRegression_NegativeZeroFloatSyntaxDefaultCoherence`.
